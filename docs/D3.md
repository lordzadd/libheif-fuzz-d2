# D3 — Working Attack and Mitigation (Track B)

## 1. Repository

- Repo: https://github.com/lordzadd/libheif-fuzz-d2
- Baseline commit (pre-mitigation, raw results): `4cb65ae1efd3f924822f823aec4cd0481b779061`
- Final commit (patch + fixed replay): `660f46878009df767927db14ba7805573c0695d7`
- Target: vendored libheif `08075aebcc0d9bf7d35f900c36114b1b6e90ed7d` (1.23.4).

The `baseline`/`final` tags were removed from history at the author's request; use the hashes above.

## 2. Setup

- **Targets:** `api_fuzzer`, `box_fuzzer`, `color_conversion_fuzzer`, `encoder_fuzzer`, `file_fuzzer`, `sequence_fuzzer`, `tile_fuzzer`. Untrusted input enters through `heif_context_read_from_memory` into the ISOBMFF box parser.
- **Toolchain:** Clang 21.0.0, CMake 3.30.5, Python 3.12.3, Linux 7.2.6-76070206-generic, 6 logical CPUs (recorded in `config.json`).
- **Engine/sanitizers:** libFuzzer with `-fsanitize=fuzzer,address,undefined,shift,integer -fno-sanitize-recover=undefined,shift,integer`; external codecs off, uncompressed codec on. Release build: libFuzzer only.
- **Data:** synthetic only — 133 upstream fixtures under `libheif/fuzzing/data/corpus` plus libFuzzer mutations; canary in `CANARY.txt`. No real user data.

## 3. Method

- **Corpus:** each target starts from a private copy of the 133 fixtures; its corpus persists across rounds and keeps every coverage-expanding unit. Crash artifacts are stored per target and de-duplicated by SHA-1.
- **Campaign:** `harness/campaign.py`, 5 rounds × 30 s per target, `-fork=2 -ignore_crashes=1`, 3 targets at once (6 nominal cores). CPU time via `getrusage`; coverage parsed from libFuzzer status lines into `coverage_over_time.csv`; function coverage via `-print_coverage=1` on the final crash-filtered corpus.
- **Analysis:** `harness/analyze.py` reproduces every artifact with a symbolized stack, groups by root cause, minimizes one representative per group, and re-runs it to confirm the same signature.
- **Replay:** `harness/replay.py` replays every unique crashing input (`-runs=1`) and the full final corpus (`-runs=0 -fork=2 -ignore_crashes=1`). Inputs, harness, settings and toolchain are identical across builds; only `D3_BUILD_DIR` changes (`build`, `build-fixed`, `build-release`).

## 4. Baseline results

**Cost:** 491.21 s wall, 1284.98 s CPU = **0.3569 CPU-hours**, 35 rounds, 226 artifact files = 219 unique inputs.

**Coverage** (first → final edges, 427 samples in `coverage_over_time.csv`):

| fuzzer | edges | fuzzer | edges |
|---|---|---|---|
| api_fuzzer | 18506 → 33688 | file_fuzzer | 16266 → 31833 |
| box_fuzzer | 7444 → 19553 | sequence_fuzzer | 10920 → 25818 |
| color_conversion_fuzzer | 359 → 7121 | tile_fuzzer | 18550 → 34223 |
| encoder_fuzzer | 676 → 6445 | | |

Corpora grew, e.g. `file_fuzzer` 84 → 836 units. Function-level counts are in `coverage_functions.csv`.

**Crashes:** all 226 artifacts reproduced; 219 unique inputs in two root-cause classes:

| class | inputs | representative | original → minimized | ASan memory error |
|---|---|---|---|---|
| C1 `bitstream.cc:115` zero-length read | 188 | `49608d53…` | 25 → **8** bytes | none |
| C2 `heif_items.cc:170` zero-length item copy | 31 | `bd0c452d…` | 813 → **308** bytes | none |

Both minimized inputs reproduce the same signature. The 8-byte C1 reproducer is `00 00 00 08 39 00 00 00` (box with zero payload).

**Root cause:** `StreamReader_memory::read()` calls `memcpy(data, &m_data[m_position], size)`. An empty `av1C` box makes `Box_av1C::parse` compute zero remaining bytes, resize a vector to 0, and pass its `data()` — which may be `nullptr` — to `BitstreamRange::read`. The wrong assumption is that `data()` is always a valid non-null `memcpy` destination. C2 is the same mistake on an empty item's data vector. The same pattern also exists in `box.cc`, `mini.cc`, `avc_boxes.cc` and `jpeg_boxes.cc`: a class of bug, not one line.

**Exploitability:** not exploitable; at most a denial of service of the sanitizer-instrumented fuzzing process. `size` is exactly 0, so no byte is read or written, ASan reports no invalid access, and the release-config replay of the same 219 inputs gives **0/226 crashes**. The abort is an artifact of `-fno-sanitize-recover`.

**Never reached:** the build disables HEVC/AV1/JPEG/JPEG2000, GDK-Pixbuf and header compression, so those paths cannot be reached; decoder-dependent paths needing a valid image are also unexercised. `-print_coverage=1` only names PC-table functions, so edge counts in `coverage_over_time.csv` are authoritative.

## 5. Mitigation

Zero-length guards in six files (52 insertions, 15 deletions): `bitstream.cc` (constructor, `read`, `BitstreamRange::read`, both `StreamWriter::write` overloads), `heif_items.cc` (C2), `heif_color.cc`, `hevc_boxes.cc`, `vvc_boxes.cc`, `context.cc`. **Scope: a whole class** — every zero-length buffer copy through these APIs becomes a well-defined no-op, fixing both observed classes and the other identical call sites. The same pattern already exists at `file.cc:1398`.

## 6. Before and after

Identical inputs (219 unique, 226 replay rows), corpora and settings; only the build changes.

| metric | baseline | fixed | release |
|---|---|---|---|
| replays that aborted | **226** | **0** | **0** |
| sanitizer signatures | 2 | 0 | 0 |
| new crash artifacts from corpus replay | 14 | 0 | 0 |

The five targets that crashed now replay every input with exit code 0. The patch removes the undefined operation itself; non-zero-length behaviour is unchanged. Corpus-replay `cov` is lower on the fixed build (fork-mode crash restarts inflate the baseline parent's cumulative count) — the campaign's `coverage_over_time.csv`, not this short replay, is the coverage measure. Limitation: the fix covers the zero-length/null-`data()` class this campaign reached, not unrelated libheif bugs.

## 7. Reproduction

```sh
git clone https://github.com/lordzadd/libheif-fuzz-d2.git
cd libheif-fuzz-d2
git checkout 4cb65ae                 # pre-mitigation
bash scripts/build.sh
D3_LABEL=baseline python3 harness/campaign.py
D3_CAMPAIGN_DIR=results/d3/baseline-20261120T173225Z python3 harness/analyze.py
D3_CAMPAIGN_DIR=results/d3/baseline-20261120T173225Z D3_LABEL=baseline python3 harness/replay.py
bash scripts/build_release.sh
D3_CAMPAIGN_DIR=results/d3/baseline-20261120T173225Z D3_LABEL=release D3_BUILD_DIR=build-release python3 harness/replay.py

git checkout 660f468                 # mitigation
BUILD_DIR="$PWD/build-fixed" bash scripts/build.sh
D3_CAMPAIGN_DIR=results/d3/baseline-20261120T173225Z D3_LABEL=fixed D3_BUILD_DIR=build-fixed python3 harness/replay.py
python3 harness/tables.py results/d3/baseline-20261120T173225Z
```

Raw results: `results/d3/baseline-20261120T173225Z/{config.json,campaign.csv,coverage_over_time.csv,coverage_functions.csv,summary.json,CANARY.txt}`, `logs/<target>/round_XX.log`, `corpora/<target>/`, `artifacts/<target>/`, `analysis/{crashes.csv,groups.csv,inputs/,logs/}`, `replay/{baseline,fixed,release}/{replay_crashes.csv,replay_corpus.csv,summary.json,logs/}`. Every number above regenerates with `harness/tables.py`.
